Harness Engineering Playbook · Spec Coding · Skill 沉淀

01
痛点诊断

四大核心痛点

团队正处于"技术范式变革"与"传统管理体制"碰撞的阵痛期。工具先行，但组织、流程、文化滞后。

1
外部趋势 vs 内部"散兵游勇"

行业已将 AI 全栈作为主流，内部停留在部分员工"自发小范围探索"，知识碎片化，无法沉淀为公司资产

2
传统分工被打破后的"角色迷茫"

前端、后台、测试边界被 AI 模糊化，新的职责边界、协同模式和转型路径完全不明确

3
重型 CMMI 管理 vs 敏捷 AI 开发

CMMI 强调严密文档和流转，AI 驱动开发追求快速迭代和即时交付，管理动作成为效率绊脚石

4
局部优秀经验无法"复制变现"

骨干有基础但无法复制给全员；AI 工具炫酷但不知如何与核心业务场景深度结合

02
解题思路

差距来自制度，不是模型

用人类时代的旧流程指挥 Agent，就像用马车交规管高速公路。制度必须跟着变。
Spec 规约驱动
→
AI 特区小组验证
→
Skill 沉淀复用

核心方法论

  • 特性驱动：以 Feature 为核心组织单元，垂直切片打破分工壁垒
  • Spec 先行：需求 → Spec → Agent 执行 → 自动验证收口
  • 闭环演进：每次业务闭环都回写知识，系统持续变好

工程化框架

  • Worktree 隔离：每个特性独立文件系统，安全并行开发
  • Context 传播：归档特性成为新特性的知识输入，Agent 不再从零开始
  • Skill 沉淀：经验封装为可复用 Skill，内部 Marketplace 分发

核心：同样的 AI 工具，有规约、有知识基座、有 AI 特区小组，阶梯才能走得通。下面看一期项目怎么落地。

04
核心成果

硬指标：一个人，能做到什么

基础数据模块 · 一周

  • 1 人 · 1 周，从零开始完成全栈开发
  • 前端 Vue + 后端 Java + MySQL 数据库，全部自动化打通
  • 实现 ~10 个业务模型的完整逻辑
  • 交付完整的前端 e2e 测试报告

测机场景 · 两周

  • 1 人 · 2 周，使用工作流快速开发
  • 从 0 → 1 完成三端服务完整 MVP 场景跑通
  • 测试服务独立开发，解耦三端依赖
  • 可多台设备并行对接，打破串行瓶颈

对金融客户意味着什么：传统模式下一个基础数据模块需要前端、后端、DBA 多人协作数周。现在 1 人 1 周即可交付——且带有完整测试报告和人工 review 确认。这不是"快了一点半点"，是数量级的提升。

04
成果一

测机业务：架构重构带来质变

之前设备对接完全靠人手工对接公司 EAP 服务。我们团队重新拆解业务，解耦三端依赖，直接对接设备——不再依赖完整的 EAP 服务部署。

改造前：人肉串行

  • 设备对接完全靠人工操作 EAP 服务
  • 必须等待完整 EAP 服务部署才能开始测机
  • 三端强耦合，一台设备卡住全部排队
  • 耗时漫长，严重制约交付节奏

改造后：解耦并行

  • 业务重新拆解，解耦三端依赖关系
  • 快速开发独立测试服务，直接对接设备
  • 不再依赖完整 EAP 部署，可多台设备并行对接
  • 效率提升数倍，为后期 Agent 转换奠定基础

关键成果：不只是"用 AI 加速旧流程"，而是从架构层面重新拆解业务。解耦三端后，每台设备可以独立并行对接，彻底打破了原来的串行瓶颈。这一步为后续 Agent 自动化奠定了架构基础。

05
成果二

LiteMES 子项目：客户自主开发产品

LiteMES 是面向中小工厂的轻量 MES 产品线。客户在我们指导下，用 Harness 快速开发 LiteMES 系统，并自主开发自定义 Skill。
掌握
客户熟练掌握 Superpower — 通过我们的培训和指导，客户团队已经能独立使用 Harness 工程框架快速开发产品
沉淀
自主开发自定义 Skills — 客户不满足于使用现成工具，开始将自身业务经验沉淀为可复用的 Skill 卡片
流程
设计 Harness 工作流 — 客户在我们帮助下完成了针对 LiteMES 业务场景的 Harness 流程设计

里程碑意义：客户从"被服务"变为"自主开发产品"。这意味着方法论和工具体系真正可复制——客户能自己快速开发产品并造 Skill，就不需要我们一直驻场。

06
质量与沉淀

质量达标 + 知识沉淀

代码质量保障

  • 生成的代码符合项目编码标准
  • 所有代码经过人工 review 确认
  • 交付完整的前端 e2e 测试报告
  • 不是"能用就行"，是达到交付标准

开发工作流沉淀

  • Feature 工作流：自动化特性开发全流程沉淀
  • Superpowers 工作流：逻辑持续丰富和积累
  • Agent / CLI / MCP 设计指导完成
  • 为二期多 Agent 协作打下技术基座

双重沉淀：开发过程中不仅交付业务代码，同时将完整的开发工作流沉淀下来。Feature 工作流 + Superpowers 工作流形成可复用的工程资产，后续新模块和新项目直接复用。客户评价非常高，目前正在洽谈二期拓展。

07
一期总结

一期成果：方向正确，效果显著

开发速度

1 人 1 周完成全栈模块（Vue + Java + MySQL），~10 个业务模型。1 人 2 周完成测机三端服务 MVP 跑通。

质量达标

代码符合项目编码标准，人工 review 确认，交付完整前端 e2e 测试报告。不是"能用就行"，是达到交付标准。

知识沉淀

Feature 工作流 + Superpowers 工作流双重沉淀。Agent/CLI/MCP 技术基座已建立，为二期多 Agent 协作打下基础。

客户认可

LiteMES 客户快速开发产品并沉淀自定义 Skill。客户评价非常高，目前正在洽谈二期拓展。

核心结论：成果证明方向正确。一人 + AI Agent 可以完成传统模式下多人团队的工作，且质量达标、知识可沉淀。二期的重点是扩大覆盖面、加速复制。

08
二期规划

二期拓展：从验证到规模化

一期验证了方向和方法。二期的核心是扩大覆盖面、深化能力沉淀、解决一期的资源瓶颈。

二期核心：Agent 创建

一期打下了 Agent/CLI/MCP 的设计基础。二期重点是创建面向业务场景的专用 Agent，从单 Agent 辅助走向多 Agent 协作。测机 Agent、实施 Agent、运维 Agent 多角色并行。

扩大 AI 特区小组

一期只有极少数人在推进。二期需要投入更多人力，组建更多 AI 特区小组，并行覆盖更多业务场景。同时加强项目管理和里程碑节奏。

Skill 市场化

一期客户已经能自主开发 Skill。二期推动 Skill 从"个人创造"到"团队共享"，建立内部 Skill 市场。LiteMES 的 Skill 直接复用到其他业务线。

09
行动清单

二期落地的关键动作

1
解决人力瓶颈。一期最大的制约是人力不足。二期必须有充足的人力投入，项目负责人需要全职投入。
2
加强项目管理。建立明确的里程碑和交付节奏，避免一期"有成果但节奏慢"的问题重现。
3
创建专用 Agent。基于一期的 Agent/CLI/MCP 基座，创建面向具体业务场景的专用 Agent，实现多 Agent 协作。
4
Skill 从点到面。一期客户已经能造 Skill。二期推动 Skill 市场化，从"个人创造"到"团队共享复用"。
5
验证更多业务场景。测机和 LiteMES 验证了方向。二期拓展到更多业务场景，用结果说话。
