Architecture Design v1.0

EQP-EAP 工厂测试 · 三端解耦架构

BS 测机服务 / 测试报告契约 / EAP 自动测试平台 — 三个系统通过结构化报告契约松耦合对接，可独立部署、独立演进、独立运行，实现工厂测试全流程自动化闭环。

1
系统总览 · 三端定位
三个独立系统，一份共享契约
核心理念：三个系统通过「测试报告」这一数据契约实现松耦合。系统 A 产出的报告，是系统 C 的唯一输入。系统 B 定义报告格式，A 和 C 各自实现生产和消费。任何一端可独立运行、替换、升级。
系统 A — BS 测机服务
网页前端操作台 + 模拟信号服务端。测机人员在浏览器中操作，服务端模拟 EQP/EAP 信号收发，完成接口逐项验证，产出结构化测试报告。
测机端
系统 B — 测试报告契约
定义标准化的测试报告 JSON Schema。包含设备信息、接口清单、测试结果、异常记录等字段。是系统 A 和系统 C 之间的唯一耦合点。
数据契约
系统 C — EAP 自动测试平台
消费测试报告，自动解析接口清单，对真实 EAP Service 发起全量验证请求。支持回归测试、版本对比、兼容性检测，零人工介入。

契约层 · 测试报告 JSON Schema
三端之间的唯一耦合点
契约是三端解耦的关键：系统 A 只需保证输出符合 Schema，系统 C 只需保证能解析符合 Schema 的输入。两端无需知道对方的实现细节。契约变更需版本管理，向下兼容。
报告结构定义
字段路径类型必填说明
reportIdstringYes报告唯一标识，UUID 格式
versionstringYes报告 Schema 版本，如 "1.0.0"
snapshot.namestringYes测试快照名称
snapshot.idstringYes快照唯一标识
snapshot.versionintegerYes快照版本号
device.modelstringNo设备型号
device.linestringNo产线标识
createdAtISO 8601Yes报告生成时间
interfaces[].idstringYes接口编号，如 EQP-EAP-001
interfaces[].namestringYes接口名称
interfaces[].direnumYes方向：upload | download
interfaces[].endpointstringYes端点路径，如 POST /api/v1/eqp/status
interfaces[].statusenumYes结果：pass | fail
interfaces[].timeMsintegerYes响应耗时（毫秒）
interfaces[].errorstringNo失败时的异常描述
interfaces[].custombooleanNo是否为自定义接口
summary.totalintegerYes总接口数
summary.passintegerYes通过数
summary.failintegerYes失败数
summary.passRatefloatYes通过率（0-1）
解耦边界 — 契约隔离
A → B 方向隔离

系统 A 只负责生产报告，不关心谁来消费。报告输出可以是文件、消息队列、API 推送，消费端无感知。

B → C 方向隔离

系统 C 只消费符合 Schema 的报告，不关心报告由谁生产。可以是 A 产出，也可以是人工录入或第三方系统。

版本兼容策略

契约版本号独立于系统版本。新字段可选添加（向下兼容），Breaking Change 需升主版本号，两端协商迁移。

传输方式无关

报告可通过文件共享、HTTP API、消息队列等任意方式传递。传输层不在契约定义范围内，两端可独立选择。

4
独立运行 · 各端自治
任一端可独立启动、测试、演进
独立运行能力是三端解耦的核心价值：系统 A 可以在没有系统 C 的情况下完成测机工作；系统 C 可以用手工构造的报告启动服务验证；系统 B 的 Schema 可以独立迭代。

系统 A · 独立运行模式

内置模拟信号服务端，无需真实 EQP/EAP 即可完成全部接口测试
测试报告本地持久化，可导出 JSON 文件，手动传递给系统 C
支持离线运行，测机人员可在无网络环境下完成测试
多设备并发测试，A1 测钻孔机的同时 A2 可测 AOI 机

系统 B · 契约独立演进

JSON Schema 独立版本管理，semver 语义化版本控制
提供 Schema 校验工具，A 和 C 各自集成校验逻辑
新字段以 optional 方式添加，保证向下兼容
提供 Mock 报告生成器，方便 C 端开发调试

系统 C · 独立运行模式

接受手工构造的 JSON 报告作为输入，无需系统 A 运行
内置 EAP Service Mock，可先于真实服务开发完成前验证测试框架
定时/触发式回归任务，对接 CI/CD 流水线自动执行
历史报告版本对比，兼容性回归结果可视化展示

Agent 智能层 · AI 增强全景
挂载于三端关键节点的智能 Agent 集群
Agent 不改架构：每个 Agent 是独立插件，挂在三端各自的事件节点上，不打破 A→B→C 的解耦关系。Agent 只做"建议"和"增强"，人工确认后才执行。数据流不变，契约层不受影响。

Layer 0 · 文档智能解析
全链路最上游，消除人工阅读说明书的瓶颈
核心价值：设备厂商提供 docx/pdf 说明书，Agent 自动提取协议参数、信号定义、寄存器地址等信息，与标准接口库对齐匹配，自动生成推荐快照草稿。将"人读文档 → 人勾选"的耗时环节压缩为秒级。

架构优势总结
独立部署 · 自由演进
三个系统独立部署、独立升级。系统 A 重构前端不影响系统 C，系统 C 切换验证框架不影响系统 A。技术栈可独立选择。
解耦
效率提升 · 并行工作
测机团队和后端团队可以并行工作。测机人员完成接口测试后立即产出报告，后端团队基于报告自动验证，消除等待时间。
效率
契约保障 · 质量可控
标准化报告契约确保三端数据一致性。Schema 校验在生产和消费两端各执行一次，杜绝格式不兼容导致的集成问题。
