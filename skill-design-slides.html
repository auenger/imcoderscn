Skill 设计模式
借鉴指南

从 UI-UX-Pro-Max 提炼可复用的 Skill 设计模式

数据分离 · 领域索引 · 合成推理 · 有状态持久化 · 渐进式加载

模式 1

四层分离架构

把 skill 知识按加载时机分四层，每层职责清晰。

Layer 0: Frontmatter~200 tokens · 触发判断
Layer 1: 决策框架~500 tokens · 流程骨架 + 工作流
Layer 2: 关键约束~1K tokens · 不可违反的硬规则
Layer 3: 数据层CSV/JSON · 按需脚本检索

核心思想

SKILL.md 只放「路由和红线」，详细知识全部外置到数据层。触发时加载轻量框架，按需检索细节。

收益

  • 上下文占用从 44KB 降到 5-8KB
  • 数据层可独立更新，不污染 SKILL.md
  • 不同场景只加载需要的知识
模式 2

零依赖 BM25 检索引擎

模式 3

领域驱动的数据索引

11 个搜索域

style / color / typography / chart / ux / product / landing / google-fonts / icons / react / web

独立配置

每个 domain 有自己的 CSV 文件、search_cols、output_cols。新增 domain 只需加一条配置。

自动检测

用户输入 "glassmorphism dark" → 自动路由到 style 域。"saas dashboard" → product 域。

可扩展

新增领域只需：1) 添加 CSV 2) 在 CSV_CONFIG 加配置 3) 在 domain_keywords 加映射。无需改代码。

领域划分让 skill 从「一个大搜索框」变成「结构化的知识路由」。AI 不需要读完全部数据，直接命中目标域。
模式 4

合成推理器：不止搜索

`--design-system` 不是简单搜索，而是聚合多个 domain + reasoning 规则的合成操作。

用户输入
"SaaS 定价页"
→
并行搜索
5 个 domain
→
Reasoning
推理规则匹配
→
合成输出
完整设计系统

五域并行

  • product → 产品类型推荐
  • style → UI 风格 + 效果
  • color → 色彩方案
  • landing → 页面结构 + CTA
  • typography → 字体搭配

Reasoning 层

  • ui-reasoning.csv 定义决策规则
  • 根据产品类型匹配推理链
  • 输出 style_priority + anti_patterns
  • 结果比单域搜索更有结构
模式 5

优先级分层：让 AI 知道轻重

不是所有规则都同等重要。用 CRITICAL → HIGH → MEDIUM → LOW 四级让 AI 知道哪些是红线。

CRITICAL
无障碍 · 触摸交互 — 违反即事故：对比度 4.5:1、触控区 44pt、焦点环可见
HIGH
性能 · 布局 · 导航 · 风格 — 影响体验：懒加载、mobile-first、底部导航 ≤5 项
MEDIUM
排版 · 动画 · 表单 — 锦上添花：line-height 1.5、动画 150-300ms、inline validation
LOW
图表 · 数据可视化 — 特定场景：legend 可见、tooltip 可达、不用颜色单独传达含义

借鉴价值：给 AI 一套「什么能违反什么不能」的决策框架。没有优先级的规则列表，AI 会同等对待所有条目。

模式 6

Master + Overrides 有状态持久化

用 `--persist` 把一次设计决策持久化到文件系统，后续 session 可复用。

design-system/
├── MASTER.md          ← 全局 Source of Truth
└── pages/
    ├── dashboard.md   ← 页面级 override
    └── checkout.md    ← 页面级 override

层级检索逻辑

  • 构建 dashboard 页 → 先查 pages/dashboard.md
  • 如果存在，override 优先于 MASTER
  • 如果不存在，直接用 MASTER 规则
  • 一次生成，多次复用

适用场景

  • 跨 session 保持设计一致性
  • 多页面项目的统一设计语言
  • 设计决策可追溯、可审计
  • 新成员 onboarding 有参考
模式 7

渐进式加载：按需逐步展开

Step 1 SKILL.md 加载
~5KB 决策框架
→
Step 2 --design-system
返回推荐方案
→
Step 3 --domain ux
补充细节规则
→
Step 4 --persist
持久化决策
每一步只加载当前需要的知识。Token 消耗与场景复杂度成正比，而不是一次性全量灌入。

设计原则

SKILL.md 是索引器和决策路由，不是百科全书。它告诉 AI「先做什么、去哪里找答案」，而不是把所有答案写出来。

Token 效率

简单任务：~2KB 就够。复杂项目：渐进加载到 ~10KB。而不是每次都花 ~44KB 的固定开销。

总结

七个可借鉴的设计模式

架构
四层分离 — Frontmatter + 决策框架 + 关键约束 + 数据层。SKILL.md 只放路由和红线。
检索
零依赖 BM25 — 纯标准库，无需 pip。对结构化知识够用，部署零摩擦。
索引
领域驱动索引 — 11 domain 独立配置，自动检测路由，新增 domain 只加配置。
合成
合成推理器 — 多域并行 + reasoning 规则，输出比单域搜索更有结构的推荐。
分层
优先级分层 — CRITICAL → LOW，让 AI 知道哪些规则不能违反。
状态
Master + Overrides — 跨 session 持久化，层级 override，设计决策可追溯。
加载
渐进式加载 — 按需逐步展开，Token 与复杂度成正比。

核心理念

好的 Skill 是高效的索引器和决策路由，不是百科全书。

把知识外置到数据层，把路由和红线留在 SKILL.md。按需检索替代全量加载，合成推理替代简单搜索，有状态持久化替代无状态重复。
