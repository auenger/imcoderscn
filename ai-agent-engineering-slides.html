AILock-Step 协议给 Agent 装上断点续传

基于状态锚点（STP）的严格线性执行协议，消除幻觉性跳步、实现绝对幂等

引言 · 问题

和 AI 协作，四个绕不开的坑

1
幻觉性跳步

看到循环任务，AI 会因上下文压力自动简化中间步骤，直接说"剩余逻辑相似，已省略"。

2
状态不可追溯

一旦生成中断，AI 很难找回执行进度，导致重复工作或遗漏任务。

3
依赖管理混乱

AI 可能在依赖未就绪时就开始实现相关功能，依赖关系层层错乱。

4
语义噪声干扰

AI 容易被代码注释或需求文档里的感性描述带偏，产出偏离目标的逻辑。

协议语法

五个符号，定义一套执行逻辑

执行器必须严格遵守"编号 → 判断 → 动作 → 跳转"的单步逻辑，只有收到明确跳转指令才能进入下一个状态锚点。

STP-XXX状态锚点执行指针必须停留在此处，所有动作围绕它展开。
?? Cond逻辑门控条件为假时跳转错误流，充当依赖哨兵。
!! OP原子算子不可拆分的物理动作，保证幂等。
>> REG数据流向将算子输出压入寄存器，供后续读取。
→ STP强制跳转唯一合法的逻辑演进路径，禁止循环。
标准算子集

四类原子算子，覆盖全流程

文件系统

  • OP_FS_READ读取，路径不存在返回空
  • OP_FS_WRITE写入或覆盖
  • OP_FS_EXISTS检查路径
  • OP_FS_DELETE删除文件或目录

Git

  • OP_GIT_STATUS获取状态
  • OP_GIT_COMMIT提交变更
  • OP_GIT_MERGE合并分支
  • OP_GIT_WORKTREE_ADD创建 worktree
  • OP_GIT_WORKTREE_REMOVE删除 worktree

数据处理

  • OP_ANALYSE非结构化 → Key-Value
  • OP_GET_TOP取符合条件的首项
  • OP_COUNT统计符合条件的数量
  • OP_CODE_GEN基于上下文生成代码

状态同步

  • OP_STATUS_UPDATE更新 .status 文件
  • OP_TASK_SYNC同步 task.md 状态
  • OP_EVENT_EMIT输出事件到日志
  • OP_UI_NOTIFY向用户发通知
方案优势

为什么是这套协议

01

消除幻觉性跳步

禁止循环语义，必须靠物理跳转重新扫描任务列表。每一轮跳转都是一次全新的状态对齐。

02

状态可追溯 · 断点恢复

每个锚点关联寄存器和物理存盘。即使中断，新会话读一次 .status 就能精准定位指针。

03

屏蔽语义噪声

冷门符号逻辑触发"指令解析模式"而非"文本续写模式"，注意力集中在算子执行上。

04

严格的依赖管理

状态锚点序列锁死路径，前置任务未标记完成，指针就无法移动到下一阶段。

实际应用

Feature Agent 的四个阶段

系统严格按 STP 步骤执行，不会跳过任何验证——这就是断点续传级开发。

01

INITIALIZATION

事件启动：读取 spec.md 与 task.md，建立初始寄存器，进入实现循环。

02

IMPLEMENT

逐个实现：取未完成任务 → 实现 → 更新进度，循环跳转直至清空。

03

VERIFY

三道闸门：lint → test → checklist，全部通过才允许进入完成态。

04

COMPLETE

收尾：git commit → 标记 status=done → 发出 EVENT:COMPLETE。

执行器不必懂"宏观意义"
只需保证每次 REG_ 转换准确无误

AILock-Step 用状态锚点强制线性、原子算子保证幂等、物理存盘实现断点续传——让 AI Agent 真正可靠地干活。
