开场

同样的 AI，不同的结果

所有人都在用 Claude、Cursor、Copilot。但团队之间的差距越拉越大。

大多数团队：体感快了

  • PR 堆积、review 排队、bug 率没降反升
  • 写代码确实快了，综合生产力远没跟上
  • 还在用人类时代的旧流程指挥 Agent

极少数团队：真正提效

  • 一人 + Agent 打通全流程，产出可靠
  • 2 人 AI 特区小组跑通一个业务场景
  • 新业务线 80-90% 代码自动化生成和测试
开场

差距来自制度，不是模型

真正提效的团队，都建立了与 AI Agent 特征匹配的工程制度。还在原地踏步的团队，依然在用为人类执行者设计的旧制度指挥 Agent。

今天不展开讲理论。我们从一个真实的泛半导体 CIM 企业案例出发，看他们怎么用 Playbook 方法论，一步步从个人提效走到组织提效。

"用人类时代的旧流程指挥 Agent，就像用马车交规管高速公路。"
案例背景

某泛半导体 CIM 企业的 AI 转型

一家专注于为泛半导体行业提供 CIM 系统整体解决方案的企业。核心产品覆盖 MOM/CIM 智能制造运营管理、IIoT 工业物联网、低代码开发平台和 ESG 双碳管理四大平台。

企业知识基座
→
测机流程 AI 特区小组（2人）
→
LiteMES 新业务线 AI 特区小组

三步走路径：先建知识基座 → 用 AI 特区小组验证场景 → 新业务线直接 Skill 化复用。这正是 Playbook「个人→团队→组织」三阶段阶梯的缩影。

案例一

知识基座：领域知识散落怎么办？

泛半导体 CIM 系统涉及设备协议、工艺流程、错误模式等大量领域知识。这些知识散落在老工程师脑子里和各处文档中。

1
新人上手慢

36 项标准接口协议，分布在不同系统和文档中，新工程师需要数月才能独立对接设备

还需进行多设备测试链路编排，复杂度指数级上升

2
经验难传承

设备响应基线、错误模式全在老员工脑子里，人员流动 = 知识流失

3
重复踩坑

同样的对接问题在不同项目中反复出现，每次都从零开始排查

案例一

Jarvis Agent：知识驱动的 Agent 架构

接口协议库
→
设备行为画像
→
错误模式库
→
Jarvis Agent

三层 Skill 体系

  • Source Knowledge — 36 项标准接口协议结构化入库
  • Repo Knowledge — 设备对接时同步积累型号响应基线
  • Workflow Knowledge — 运维排障时持续回写错误模式

知识飞轮

  • 企业核心知识从"人脑"迁移到"Agent 可查"
  • 新场景开发不再从零开始
  • 每次业务闭环都回写新知识，越用越准
  • 为后续两个 AI 特区小组提供统一知识基座
案例一 · Playbook 映射

知识基座验证了什么？

→ Playbook 卷二「规模化 Agent 开发」核心：跨会话记忆工程

Jarvis 的 Source/Repo/Workflow 三层正是 Playbook 所说的"让 Agent 知道病历本"。Agent 每次不是"新员工的第一天"，而是带着历史知识上岗。

→ 核心原则「演进」

知识不是一次性建好的。每次业务闭环都回写新知识，系统持续演进。这是 Playbook 演进原则的典型实践。

→ 实战教训：知识先行

没有知识库的 Agent 就是空壳。先建基座，再让 AI 特区小组消费知识——这个顺序不能反。

案例二

测机流程：设备对接三端联调之痛

设备对接场景：厂商设备 → 测机服务 → EAP，三端联调。这是 CIM 行业最典型的效率瓶颈。

改造前

  • 多人分工，靠经验排查三端问题
  • 错误定位靠人工逐端排查，耗时数小时
  • 经验只在老员工脑子里
  • 同样的问题在不同项目反复出现

改造目标

  • Agent 编排引导测试步骤
  • 自动判定结果，Fail 秒级定位错误端
  • Agent 查询知识库获取接口协议和设备画像
  • 经验持续沉淀，不再重复踩坑
案例二

2 人 AI 特区小组：测机业务场景重构

一个技术人员 + 一个实施业务负责人，组成 AI 特区小组，对长期遗留的测机业务流程进行全面重构。

业务重构
通过 Harness 工程进行业务场景重构。大量编码工作由 Harness 自动化完成，技术人员设计 Agent 工作流，实施负责人定义业务规则。
自动化编码
重构后的业务场景大幅度缩减实施成本。遗留多年的业务债务在 Harness 工程框架下被系统性清理，2 人解决了长期遗留的业务债。
沉淀
与 Jarvis 知识基座关联。Fail 时秒级定位错误端（设备/EAP/MES），每次闭环都回写新的设备响应特征和错误模式。

设备对接场景下效率提升 3-5 倍。重构后的业务场景大幅缩减实施成本，错误定位速度从小时级降到秒级。

案例二 · Playbook 映射

AI 特区小组验证了什么？

→ Playbook 卷三「治理百倍速的组织」核心：AI 特区小组模式

划出小团队跑通流程，不受传统管理约束，以结果为准。这正是 Playbook 所说的"反脆弱精英组织"——聪明但独立的小团队，用结果说话。

→ 核心原则「闭环」

测机流程本身就是闭环：测试步骤 → 执行结果 → 错误诊断 → 知识回写。每一步都有明确的输入和验证。

→ 实战教训：知识基座是前提

测机 Agent 能做到秒级定位，前提是 Jarvis 知识库已经有了接口协议和设备画像。没有卷一「可靠的 Agent 编程」的积累，卷二「规模化 Agent 开发」就是空中楼阁。

案例三

LiteMES 新业务线：80-90% 代码自动化

面向中小工厂的轻量 MES 产品线。另一个 AI 特区小组直接启动全新业务线。

Harness 工作流
规约驱动的完整开发流程。Spec 定义需求 → Agent 生成代码 → 自动化测试收口。非业务细节功能实现 80-90% 代码自动化编码和测试。
Skill 沉淀
针对 LiteMES 设计开发工作流 Skill。将产品线的通用开发模式沉淀为 Skill，后续交付直接复用于客户二次开发。
市场拓展
标准化功能的开发效率大幅提升。交付团队可以将精力集中在客户业务差异化上，Skill 直接用于交付。
案例三 · Playbook 映射

新业务线验证了什么？

→ Playbook 卷一「可靠的 Agent 编程」核心：规约驱动 + 验证闭环

LiteMES 用 Harness 工作流实现了完整的 Spec → Agent 执行 → 测试收口。80-90% 的代码自动化率证明：规约到位，Agent 的产出可以非常可靠。

→ 核心原则「演进」的终极形态

Skill 沉淀是演进的终极形态。每个 AI 特区小组的经验不只是文档，而是可以直接执行的 Skill。新业务线不是从零开始写代码，而是从 Skill 库中组合工作流。

→ 实战教训：Skill 是效率倍增的关键

没有 Skill 沉淀，每次都是新项目。有了 Skill，交付变成配置+定制，效率成倍放大。

2

方法论提炼

从案例中提炼 Playbook

三个案例指向同一套方法论。Playbook 不是凭空设计的框架，而是从大量真实项目中提炼的工程规律。

卷一「可靠的 Agent 编程」— 个人提效：规约与验证

LiteMES 的 Spec→Agent→测试闭环，就是卷一的完整实践。规约将模糊变为确定，验证闭合反馈回路。

卷二「规模化 Agent 开发」— 团队提效：记忆与并行

Jarvis 知识基座的 Source/Repo/Workflow，就是卷二的跨会话记忆工程。从对话伙伴变成任务设计者。

卷三「治理百倍速的组织」— 组织提效：AI 特区小组与治理

2 人 AI 特区小组重构测机流程，就是卷三的组织模式。小团队跑通验证，经验扩散。

核心原则

闭环：保证每一步可靠

所有案例中都出现了同一个模式——反馈回路。

明确输入
→
Agent 执行
→
自动验证
→
偏差纠正

案例中的闭环

  • Jarvis：每次业务闭环回写知识
  • 测机：测试→判定→诊断→回写
  • LiteMES：Spec→代码→测试收口

为什么必须闭环

  • Agent 不会自我检查
  • 开环系统小规模勉强可用，长期必然失控
  • 反馈环必须被显式工程化到系统中
核心原则

演进：保证系统越来越好

Agent 会忠实复制代码库中已有的模式，包括坏的模式。合并后的代码成为后续生成的参考集。

没有持续演进，系统会自我强化地滑向退化。规约、测试、Skill 卡片、组织流程，每一层都需要持续演进。

执行
→
沉淀知识/Skill
→
更新规约
→
更好的执行

闭环保证每一步可靠，演进保证系统越来越好。两个原则相互支撑，缺一不可。

三阶段阶梯

个人 → 团队 → 组织

三个案例恰好对应 Playbook 的三阶段阶梯。每个阶段有前提条件，跳不过去。

卷一「可靠的 Agent 编程」— 个人提效：规约 + 验证

前提：学会写 Spec、建测试。从 Vibe Coding 进入工程模式。

卷二「规模化 Agent 开发」— 团队提效：记忆 + 并行

前提：卷一过关。有了规约和验证，才能放手让 Agent 自主执行、多 Agent 并行。

卷三「治理百倍速的组织」— 组织提效：AI 特区小组 + 治理

前提：卷二过关。有了知识基座和 Skill 体系，才能在组织层面复制成功模式。

"每个阶段有前提条件。跳过个人提效直接搞组织提效，就像没学会走就要跑。"
收尾

行动清单

1
自己先用起来。用 AI 做日常的事，体感不用不会有。不需要成为程序员，但需要理解"跟 AI 协作"意味着什么。
2
建知识基座。把团队的核心知识结构化，让 Agent 可查。这是所有后续工作的地基。
3
找到你的 AI 特区小组。划出小团队跑通流程，验证方法论，再把经验扩散。
4
建立规约和测试。从今天开始，每个 bug 和新功能都写 spec，先跑通闭环再追求速度。
5
Skill 沉淀。每个 AI 特区小组的经验沉淀为可复用的 Skill，实现效率的倍增。
