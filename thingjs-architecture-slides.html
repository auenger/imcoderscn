技术架构

Thing.js 分层架构：应用-场景-对象

Thing.js 采用"应用-场景-对象"三层抽象模型，通过层级隔离将 3D 开发复杂度逐层收敛。

APP new THING.App() — 初始化全局应用实例，管理生命周期
SCENE app.load() — 加载森工厂 / ThingBuilder 预置 3D 场景
OBJECT app.query() — 类 CSS 选择器检索和操作场景内对象
RENDER WebGL 协议渲染 — 顶点着色器 + 片段着色器
RUNTIME Chrome / Firefox / Edge / IE11+ — 跨终端运行

核心抽象：开发者只需关注应用层逻辑，场景加载、对象管理、渲染管线全部封装在框架内部。类 DOM 操作方式（app.query()）让前端工程师无需图形学背景即可上手。

挑战

WebGL 画布的"黑盒"属性

所有 3D 内容渲染在单一 <canvas> 元素内，对浏览器而言只是一个频繁更新的像素缓冲区。传统 DOM 测试工具全部失效。

DOM 定位失效

  • page.locator('#obj') 返回 null
  • 3D 对象不存在于 DOM 树中
  • CSS 选择器无法命中画布内容

可访问性树缺失

  • WebGL 内部交互对象对辅助技术不可见
  • 除非手动 ARIA 映射
  • 无头浏览器无法感知 3D 内容

渲染异步状态

  • 纹理和几何数据加载耗时长
  • 常规 page.load 检查无法判断 3D 就绪
  • 需要监听特定加载完成事件

硬件渲染差异

  • 不同 GPU 驱动导致渲染细微差异
  • 抗锯齿 / 着色器精度不一致
  • 像素对比测试误报率高
Playwright 方案一

坐标驱动 + 内部状态透传

通过 page.evaluate() 注入 Thing.js 运行环境，直接查询内部 API 获取 3D 坐标，转换为屏幕像素坐标后模拟交互。

// Step 1: 通过 Thing.js 内部 API 获取 3D 对象屏幕坐标
const screenPos = await page.evaluate(() => {
  const obj = window.app.query('#device-001')[0];
  return window.app.camera.worldToScreen(obj.position);
  // → { x: 640, y: 320 }
});

// Step 2: 使用屏幕坐标模拟点击
await page.mouse.click(screenPos.x, screenPos.y);

// Step 3: 验证 DOM 层反馈（弹窗 / Tooltip）
await expect(page.locator('.device-detail')).toBeVisible();

局限

  • 对相机角度敏感，视角一变坐标就失效
  • 需要应用暴露 window 级 API

优势

  • 能模拟真实用户交互逻辑
  • 验证完整业务流程，精准度高
Playwright 方案二

视觉回归 + Testing Mode

将当前页面状态与"黄金标准"截图对比。关键是在 Thing.js 应用中内置 Testing Mode，消除渲染不确定因素。

冻结
状态冻结 — URL 含 ?testing=true 时，停止所有 3D 动画、物理模拟和随机粒子效果
锁定
固定相机 — 锁定在预定义坐标 (x:0, y:50, z:100)，确保每次截图取景完全一致
注入
数据注入 — 绕过真实 IoT 数据流，通过参数注入预设状态 ?color=red&alarm=true
// 视觉回归测试：在 Testing Mode 下截图对比
await page.goto('http://app/?testing=true&color=red&alarm=true');
await page.waitForFunction(() => window.__SCENE_LOADED__ === true);
await expect(page).toHaveScreenshot('fire-alarm.png', {
  maxDiffPixelRatio: 0.05,  // 容忍 5% 像素差异（硬件差异）
  threshold: 0.3
});

Testing Mode 本质：把非确定性的 3D 渲染变成确定性的"快照"。通过控制变量（相机、动画、数据），让截图对比从"碰运气"变成"可复现"。

AI Agent

Agent Browser：性能、成本与确定性

高延迟

每步需上传图片 + LLM 推理。约每分钟 20 步交互，远慢于脚本化方案。

成本消耗

频繁调用多模态模型（GPT-4o / Claude 3.5）。大规模回归测试 Token 费用显著。

确定性缺失

AI 决策具有概率性，多次测试可能不一致。不适合严谨的回归测试场景。

脚本化 Playwright

  • 速度快，毫秒级执行
  • 完全确定，可重复
  • 适合高频回归测试
  • 但维护成本高，需硬编码

视觉 AI Agent

  • 灵活，自然语言驱动
  • 适应 UI 变化，低维护
  • 适合复杂场景探索
  • 但慢、贵、不确定

定位差异：Playwright 负责"确定性的回归验证"，Agent Browser 负责"探索性的复杂场景验证"。两者互补，不是替代关系。

安全

WebGL 指纹识别与隐匿策略

高级安全系统（DataDome / Cloudflare）会监控 WebGL 参数识别自动化行为。无头浏览器特征极易暴露。

GPU 信息查询

WEBGL_debug_renderer_info 获取 GPU 型号。"SwiftShader" = 无头环境，直接判定机器人。

渲染特征分析

要求渲染特定 3D 场景并计算像素哈希。无头环境渲染细微差异暴露身份。

属性一致性检查

navigator.webdriver === true 或 Canvas 指纹与 WebGL 硬件不匹配，连接被切断。

对抗策略

  • 指纹模拟：伪造 Canvas / WebGL 参数 / 字体列表
  • 行为拟人化：非线性鼠标移动 + 随机打字延迟
  • 代理路由：住宅代理避免数据中心 IP 封锁

推荐工具

  • GoLogin：反检测浏览器，多会话指纹隔离
  • Browserbase：云端浏览器基础设施，内置指纹掩蔽
  • Playwright Stealth：插件级隐匿增强
综合方案

方案一：混合型 Playwright 框架

适用于内部 QA 流程 — 高频运行、低延迟、完全确定 QA 团队

基建
建立 Playwright 测试套件，集成到 CI/CD 流水线。每次代码变更自动触发全量回归。
白盒
注入全局辅助对象 window.__TEST_HELPER__，将 3D 物体 ID 映射为屏幕坐标，暴露场景加载状态。
同步
异步状态同步化，利用 Playwright 自动等待 + Thing.js onComplete 事件，确保场景完全加载后断言。
视觉
关键节点视觉断言，在触发告警等关键业务节点截图，使用 maxDiffPixelRatio: 0.05 容忍硬件差异。

方案二：AI 视觉 Agent 方案

适用于复杂场景 / 第三方接入 — 无源码权限、UI 频繁变化 复杂场景

选型
工具选型：browser-use 框架 + Claude 3.5 Sonnet / GPT-4o 视觉模型。自然语言驱动测试流程。
指令
指令驱动："检查主变压器是否显示异常温度，如果是，点击查看详细日志"。Agent 自主完成多步操作。
反馈
闭环反馈：每步操作后截图验证视觉状态变化。弹窗是否出现？颜色是否变红？Agent 自主判断。
HITL
人工在环机制：AI 无法识别特定 3D 特效时暂停，提示人工介入。解决后恢复自动化流程。

适用边界：当项目处于早期 UI 频繁变动、或测试第三方系统无法注入代码时，Agent 方案的低维护成本优势明显。但不适合替代 CI 回归——延迟和成本不允许。

总结

从架构到测试：完整技术路径

1
Thing.js 架构 — 应用-场景-对象三层抽象，WebGL 底层渲染，IoT 实体行为化建模。
2
测试挑战 — Canvas 黑盒、DOM 失效、异步加载、硬件差异。传统工具全部碰壁。
3
Playwright 三方案 — 坐标驱动（精准）、视觉回归（Testing Mode 消除不确定性）、CanvasGrid（兜底）。
4
Agent Browser — 视觉驱动操作，适应 UI 变化，但慢、贵、不确定。定位为探索性验证。
5
安全隐匿 — WebGL 指纹检测与对抗策略。生产环境测试必须过这一关。
6
三套综合方案 — 混合 Playwright（QA）、AI 视觉 Agent（复杂场景）、无头运营（批量巡检）。

结论与展望

  • Thing.js 的 WebGL 架构为自动化测试设置了天然屏障
  • Playwright 可行，但必须超越 DOM 定位思维 — 坐标+状态评价
  • Agent Browser 为非结构化 3D 交互提供新路径
  • 灵活组合"脚本化"与"视觉 AI"两套工具链
  • WebGPU + 多模态大模型 → 更智能、语义化的自动化未来
"数字孪生的自动化测试，本质是在黑盒中建立白盒的认知。脚本管确定性，AI 管灵活性，两者互补才是正解。"
