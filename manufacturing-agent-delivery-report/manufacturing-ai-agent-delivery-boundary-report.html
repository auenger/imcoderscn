生产制造 AI Agent 项目交付边界分析

以现有 MES 为可信数据源，明确产品形态、平台边界、交互渠道、权限模型与技术基座。

汇报对象：公司管理层与项目决策组 报告日期：2026-07-17 建议阶段：立项与售前范围确认
客户使用入口Web 工作台为标准入口，IM 作为可选渠道

结论先行

推荐采用“平台承载、能力解耦、分层交付”的方案

本项目优先基于公司现有 Agent 平台实施，以降低重复建设和运维成本；同时通过标准化 MES 数据服务、Agent 服务接口和渠道适配层控制耦合。客户购买的是四类业务 Agent 能力及其运行服务，不默认获得平台源代码、通用 Agent 开发能力或无限制连接器能力。

实施方保护原则：只对已冻结的数据范围、业务问题、输出形式和验收样本承担交付责任。数据缺失、口径变化、客户新增场景、第三方系统限制及模型天然不确定性，不应被归入原合同内的无条件效果承诺。

本期建议必交

工厂内部可用的四类业务 Agent

覆盖产能分析、历史数据分析、计划模拟与预测性报告，提供 Web 入口、MES 对接、权限校验、日志审计、基础运营和验收指标。

条件性交付

IM Gateway 与客户自定义能力

钉钉等 IM 接入、客户自建 Agent、通用连接器市场和开放平台能力应单独报价、单独验收。

管理层需要记住的四句话

01

交付业务结果

交付可验收的制造业务能力，不把底层平台全部能力自动打包给客户。

02

Web 先于 IM

Web 工作台承载完整体验和复杂结果，IM 只作为轻量问答、通知和审批入口。

03

权限必须双重校验

既约束 Agent 能做什么，也约束当前用户能看什么，不能让 Agent 绕过 MES 权限。

04

替代基座不是捷径

OpenClaw、Hermes 可用于验证，但企业交付仍需补齐身份、审计、权限、运维和版本治理。

建议交付范围矩阵

合同范围必须按“业务 Agent、平台能力、数据工程、渠道与运维”拆分，避免客户将示范能力理解为完整平台授权。

四类 Agent 的最低可验收定义

产能分析 Agent

按约定组织、产线、设备、班次与人员维度查询产能，解释指标来源，识别异常与瓶颈，并可追溯至 MES 明细。

数据分析 Agent

对不少于约定周期的设备与人员历史数据进行趋势、对比、异常和相关性分析，输出结论、证据和数据时间范围。

计划模拟 Agent

读取周计划、产能约束、设备状态、人员能力与历史节拍，生成候选日计划，并清晰展示约束、冲突和人工调整点。

预测性报告 Agent

按约定周期生成生产趋势、异常风险、预测区间、影响因素与建议动作。预测结论必须附带置信度或适用条件。

验收不应只看“能否聊天”

建议同时验收数据正确性、口径一致性、权限隔离、响应时效、可解释性、稳定性、人工兜底和审计完整性。计划模拟与预测结果属于辅助决策，最终生产指令仍由授权人员确认。

六项交付边界问题分析

以下判断可直接转化为产品方案、合同条款和技术设计输入。

推荐：基于现有平台

1. 交付物应采用什么产品形态

建议形态：“制造 AI Agent 应用套件 + 公司 Agent 平台运行服务 + MES 数据适配服务”。客户前台看到的是制造业务应用，后台由公司平台承载 Agent 编排、模型管理、连接器、日志和运营。

边界说明：本期交付的是指定场景的可运行实例及使用权，不等同于整套平台产品、全部平台功能或平台源代码。部署模式可根据客户安全要求选择客户本地、专有云或混合部署，但必须单独核算基础设施和运维责任。

管理决策：统一将公司平台定义为产品底座，将四类制造 Agent 定义为行业应用包。
推荐：受控开放

2. 自定义 Agent 和连接是否交付

建议分级：标准版只交付已经配置并验收的 Agent 与连接。增强版可开放“参数级配置”和经过审核的连接器。开发者版才开放 Agent 创建、工具编排、发布审批和测试环境。

如果直接开放全部自定义能力，客户新增 Agent 后产生的安全、模型费用、数据泄露、稳定性和效果问题会回流为项目责任。开放能力必须配套沙箱、工具白名单、发布审批、版本回滚、调用限额和责任边界。

合同建议：写明可创建数量、连接器范围、管理员席位、发布流程、支持范围与二次开发责任。
推荐：第二阶段可选

3. 是否需要 IM Gateway

建议：核心交付先以 Web 工作台为主，IM Gateway 作为可选渠道适配层。IM 适合查询、提醒、报告推送、确认与轻量审批；复杂图表、计划对比、数据钻取和权限配置仍回到 Web。

接入钉钉或其他 IM 不是增加一个 Bot 就结束，还涉及账号绑定、组织同步、消息幂等、会话隔离、文件安全、卡片兼容、超时重试、审批留痕和平台限流。

进入条件：客户明确高频移动使用场景，并确认企业应用审批、身份映射方式和渠道运维责任。
推荐：运行绑定，接口解耦

4. Agent 是否强绑定平台，是否只供工厂内部使用

建议：商业交付层面绑定公司 Agent 平台的运行与服务体系，技术层面通过标准接口避免业务逻辑和单一平台不可拆分。Agent 逻辑应以版本化配置、工具协议和数据契约沉淀。

第一阶段只面向客户工厂内部员工，包括管理者、计划员、班组长、设备人员和授权分析人员。供应商、外协、经销商等外部主体涉及新的身份域、数据边界和法律责任，应视为新增场景。

架构要求：平台可替换不代表本期必须支持双平台运行，接口可替换性应作为技术资产保留。
推荐：双主体授权

5. Agent 与用户的数据权限如何处理

建议模型：采用“Agent 服务身份 + 当前用户身份”的交集权限。Agent 服务身份决定可调用哪些工具和数据域，当前用户身份决定可查看哪些工厂、车间、产线、设备、人员和字段。

Agent 可被视为 AI 员工并拥有独立账号，但不能只给 Agent 一个高权限账号后让所有用户共享。每次调用需要记录用户、Agent、意图、数据范围、工具参数、结果摘要与时间，敏感操作必须二次确认或进入审批。

安全底线：最终有效权限 = 用户权限 ∩ Agent 权限 ∩ 场景策略，任何一层拒绝都必须终止调用。
推荐：作为备选验证

6. 是否可用 OpenClaw 或 Hermes 作为 AI 员工基座

判断：可以用于原型、专项 Agent 或隔离环境验证，但不建议在现有平台可满足需求时直接替换主交付架构。它们偏向个人或通用自治 Agent 运行时，消息渠道、工具、记忆和任务能力较强，但制造企业交付还需要补齐统一身份、细粒度数据权限、审批审计、多租户、版本治理、SLA 与安全运营。

如果公司平台在工具扩展、长任务、IM Gateway 或私有部署方面存在硬性缺口，可开展 2-4 周受控验证。验证对象应是企业能力差距，不是单纯比较对话效果。

选型门槛：只有当替代方案在关键能力、总成本和交付周期上形成明确优势，并通过安全评审，才进入正式架构。

推荐技术架构

核心原则是渠道可替换、Agent 运行时可演进、MES 数据服务稳定、权限策略集中执行。

交互与身份层

  • Web 工作台
  • 可选 IM Gateway
  • 统一登录与组织映射
  • 会话与用户上下文
→

Agent 平台层

  • 四类业务 Agent 编排
  • 模型路由与提示策略
  • 工具白名单与任务状态
  • 日志、评测与运营监控
→

MES 数据服务层

  • 指标语义与数据契约
  • 用户数据范围过滤
  • 时序与历史分析服务
  • 计划模拟与预测服务

平台内部需要稳定的接口

  • Agent Definition：Agent 配置、版本和发布状态
  • Tool Contract：工具参数、返回结构、错误码和权限标签
  • Identity Context：用户、组织、角色和数据范围
  • Trace Event：问题、调用链、耗时、成本和结果状态

MES 侧需要沉淀的公共能力

  • 统一设备、人员、工单、班次和产线主数据
  • 产能、达成率、稼动率、节拍等指标口径
  • 面向 Agent 的聚合 API，避免直接生成任意 SQL
  • 数据新鲜度、缺失率和异常值的质量标记

权限模型建议

有效权限由三层取交集

用户权限控制谁能看什么；Agent 权限控制这个 AI 员工允许做什么；场景策略控制本次任务在什么条件下可以执行。

查询类操作

沿用 MES 组织与数据范围，结果按工厂、车间、产线、设备、人员和敏感字段过滤。报告缓存也必须带权限标签。

动作类操作

创建计划、修改参数、发送通知等动作默认要求人工确认。高风险动作进入审批，禁止模型直接提交生产控制指令。

AI 员工身份

每个 Agent 使用独立服务身份、最小权限和独立密钥，禁止多个 Agent 共享高权限账号，禁止把密钥写入提示词或连接器配置明文。

审计与追责

审计至少包含发起用户、Agent 版本、模型、数据范围、工具参数、结果、确认人、异常和成本。日志保留周期写入合同。

平台与替代基座的决策比较

决策维度公司 Agent 平台OpenClaw / Hermes 类基座建议
现有资产复用可复用模型、连接器、运营和团队经验需要重新适配 MES 与内部规范平台优先
业务交付一致性便于形成统一产品和售后体系灵活，但容易形成第二套技术栈平台优先

适用位置主生产交付架构隔离试验、专项能力或备用方案主次分明

实施方交付防守重点

Agent 项目最容易被挑战的原因不是功能完全不可用，而是客户对“智能化”的理解与合同验收标准不一致。实施方必须把模糊期待转化为可测量、可追溯、附带前置条件的交付承诺。

核心原则：不承诺抽象智能，只承诺限定条件下的业务能力

不要使用“准确理解所有问题”“自动完成智能排产”“预测设备故障”“像专家一样分析”等无法封闭验收的表述。所有能力必须绑定指定用户、指定数据、指定问题类型、指定输出和指定验收样本。

高风险承诺

必须避免写入合同或汇报

  • Agent 能回答所有生产经营问题
  • 预测准确率长期固定且不受数据变化影响
  • 计划结果一定优于人工计划
  • 所有 MES 数据无需治理即可直接使用
  • 客户可任意增加 Agent、用户、工厂和连接器
  • 大模型升级后效果只会提升、不会退化
  • 第三方 IM、模型和接口长期稳定可用
可交付承诺

建议使用的责任表述

  • 支持约定清单内的问题类型与分析维度
  • 基于双方确认的数据集和时间窗口验收
  • 输出候选计划、约束说明和人工确认点
  • 对数据质量问题进行识别、标记和告警
  • 新增范围通过变更单评估工期与费用
  • 模型版本冻结，升级前执行回归测试
  • 第三方能力按其官方 SLA 和接口限制执行

客户最可能提出的挑战

客户挑战产生原因实施方提前准备建议验收证据
“为什么这个问题回答不出来” 客户将 Agent 理解为无限范围通用助手 冻结意图清单、问题示例、拒答范围和转人工机制 场景覆盖矩阵、标准问法与边界问法测试记录
“数据和 MES 报表不一致” 指标口径、时间边界、过滤条件或数据延迟不同 建立指标字典、数据血缘、截止时间和对账样本 SQL 或 API 版本、样本明细、双方签字的对账结果
“分析结论不够智能” “智能”没有验收定义，客户预期不断提高 把智能拆为趋势、异常、原因候选、建议和依据 固定测试集、专家评分表、基线方案对比
“预测不准，所以项目失败” 未约定预测对象、周期、误差指标和数据稳定性 定义基线、容差、置信区间、适用条件和重训触发器 滚动验证报告、误差分布、异常期间剔除规则
“计划不能直接执行” 忽略隐性规则、临时插单和现场经验 定位为候选计划，明确约束覆盖率与人工调整点 约束清单、冲突解释、计划员确认与调整记录
“钉钉能聊，为什么不能完成所有操作” 把渠道入口误认为完整业务系统 定义 IM 支持的消息类型、操作清单和 Web 跳转边界 渠道能力清单、消息模板、异常和超时测试
“新增需求应该包含在 Agent 里” Agent 的自然语言形态让需求看起来只需改提示词 将新增意图、工具、数据源、角色和报告视为范围变更 需求基线、变更单、工作量评估和版本发布记录

实施方必须锁定的八类文件

范围基线

Agent 清单、用户角色、工厂范围、数据源、问题类型、输出形式、语言、终端和并发规模。

数据责任清单

字段、口径、历史周期、刷新频率、质量要求、缺失处理、客户数据负责人和问题关闭时限。

场景测试集

正常问题、边界问题、错误输入、越权问题和拒答问题。测试集须由双方确认并版本冻结。

验收指标表

正确性、覆盖率、引用可追溯、响应时间、稳定性、权限隔离及人工评价的计算方式。

客户配合清单

账号、网络、接口、样本、专家时间、测试环境、业务确认人和反馈时限。延迟应触发计划顺延。

变更控制单

新增数据源、连接器、Agent、意图、报表、用户范围、模型和部署要求都需重新评估。

上线与回退方案

模型和提示版本、发布审批、灰度范围、故障降级、人工入口、回滚条件和责任联系人。

运行证据包

版本记录、测试结果、调用日志、权限日志、数据快照、问题单、培训签到与验收签字。

建议写入合同的责任边界

客户责任

  • 保证提供的数据、接口、账号和业务规则合法、真实、完整且按期可用
  • 指定有决策权的业务负责人确认指标口径、样本和验收结论
  • 负责 MES 源数据修复、现场流程执行和最终生产决策
  • 按约定提供网络、服务器、安全策略和第三方平台授权
  • 在规定时间内反馈，超期未反馈的处理机制需在合同中约定

实施方责任

  • 按冻结范围完成配置、集成、测试、培训和上线
  • 对平台缺陷和约定范围内的问题提供修复
  • 对模型输出提供来源、限制和必要的风险提示
  • 落实最小权限、日志审计和敏感操作确认
  • 对新增需求提供评估，不默认无偿纳入

必须明确的免责与限制

Agent 输出属于辅助分析，不构成未经人工确认的生产指令。因源数据错误、客户未披露规则、第三方服务中断、客户越权配置、未经批准的模型或提示修改造成的结果偏差，不应认定为实施方交付缺陷。具体措辞应由法务结合项目合同确认。

项目过程中的交付门禁

启动门禁

前置条件没有满足，不进入开发

范围、数据接口、负责人、环境、样本和验收口径至少形成书面基线。缺少关键输入时提交风险告知和计划影响。

数据门禁

数据没有对账，不开始评价 Agent 效果

先证明数据查询与 MES 一致，再评价模型分析。数据问题与 Agent 问题必须使用不同的问题分类。

效果门禁

固定版本、固定测试集、固定评价人

验收期间冻结模型、提示、工具和数据快照。客户临时问题可以记录，但不能替代正式测试集。

上线门禁

权限、回退和人工兜底必须可用

未完成越权测试、审计检查、故障降级和用户培训，不建议开放生产用户。

验收门禁

按证据逐项签署，不接受无限期试用

验收按功能包或里程碑拆分。问题按缺陷、数据问题、优化项和新增需求分类，不让优化项阻塞已完成范围验收。

建议实施路径

边界确认

确定数据、用户、指标和验收

冻结 MES 数据清单、指标口径、角色范围、部署模式、模型来源、调用预算与非功能指标。形成正式范围基线。

基础打通

先完成数据服务与权限闭环

建立 MES 聚合 API、身份映射、Agent 服务账号、工具白名单和审计链路。用确定性查询验证数据正确性。

场景试点

优先上线产能分析与数据分析

这两个场景依赖较少、价值直观，可帮助校准数据口径。计划模拟先做建议，不直接写回 MES。

预测扩展

形成计划模拟与预测报告闭环

积累反馈样本，建立基线模型、预测误差监控、人工确认和报告订阅机制。

渠道增强

按真实使用频率接入 IM

在 Web 场景稳定后，再接入钉钉等渠道，先做报告推送与查询，最后评估审批和动作能力。

主要风险与控制建议

数据口径不一致

同一产能指标在 MES、报表和业务人员之间定义不同。先建立指标字典与样例数据验收。

项目范围持续扩张

客户把平台演示能力视为默认交付。用范围矩阵、版本许可和变更流程控制。

权限穿透与敏感泄露

Agent 使用高权限服务账号绕过用户权限。实施交集授权、字段过滤和权限感知缓存。

预测被误当生产指令

业务直接执行未经确认的建议。明确辅助决策定位，为高风险操作设置确认和审批。

IM 体验替代业务系统

复杂任务被塞入聊天窗口，导致结果不可读、无法钻取。IM 提供轻入口，Web 承载完整流程。

双技术栈增加维护成本

同时维护公司平台和开源基座。替代基座只做受控验证，通过架构评审后才能生产化。

建议管理层本次确认的事项

产品与商业

  • 四类 Agent 是否定义为制造行业应用包
  • 平台采用订阅、许可还是项目制授权
  • 客户自定义与 IM 是否独立报价

客户与用户

  • 本期仅限工厂内部员工是否成立
  • 首批用户角色和工厂范围
  • 是否存在外协或集团跨组织使用

技术与安全

  • 部署在客户本地、专有云或混合环境
  • 权限以 MES 为主还是统一身份平台为主
  • 模型服务、数据出域和日志保留要求

交付与验收

  • 数据正确率、时效和稳定性指标
  • 预测场景的基线与容差
  • 质保、持续调优和模型费用责任

建议立项结论

同意以公司 Agent 平台为首选底座，启动制造行业应用包试点。第一阶段交付 Web 入口、MES 数据服务、双主体权限、四类 Agent 中的产能与数据分析能力；计划模拟和预测报告分阶段验收；IM Gateway、自定义 Agent 与替代基座验证列为可选工作包。
