结论先行

推荐采用“平台承载、能力解耦、分层交付”的方案

本项目优先基于公司现有 Agent 平台实施，以降低重复建设和运维成本；同时通过标准化 MES 数据服务、Agent 服务接口和渠道适配层控制耦合。客户购买的是四类业务 Agent 能力及其运行服务，不默认获得平台源代码、通用 Agent 开发能力或无限制连接器能力。

实施方保护原则：只对已冻结的数据范围、业务问题、输出形式和验收样本承担交付责任。数据缺失、口径变化、客户新增场景、第三方系统限制及模型天然不确定性，不应被归入原合同内的无条件效果承诺。

本期建议必交

工厂内部可用的四类业务 Agent

覆盖产能分析、历史数据分析、计划模拟与预测性报告，提供 Web 入口、MES 对接、权限校验、日志审计、基础运营和验收指标。

条件性交付

IM Gateway 与客户自定义能力

钉钉等 IM 接入、客户自建 Agent、通用连接器市场和开放平台能力应单独报价、单独验收。

管理层需要记住的四句话

01

交付业务结果

交付可验收的制造业务能力，不把底层平台全部能力自动打包给客户。

02

Web 先于 IM

Web 工作台承载完整体验和复杂结果，IM 只作为轻量问答、通知和审批入口。

03

权限必须双重校验

既约束 Agent 能做什么，也约束当前用户能看什么，不能让 Agent 绕过 MES 权限。

04

替代基座不是捷径

OpenClaw、Hermes 可用于验证，但企业交付仍需补齐身份、审计、权限、运维和版本治理。
