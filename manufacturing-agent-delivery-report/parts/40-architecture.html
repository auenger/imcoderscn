推荐技术架构

核心原则是渠道可替换、Agent 运行时可演进、MES 数据服务稳定、权限策略集中执行。

交互与身份层

  • Web 工作台
  • 可选 IM Gateway
  • 统一登录与组织映射
  • 会话与用户上下文
→

Agent 平台层

  • 四类业务 Agent 编排
  • 模型路由与提示策略
  • 工具白名单与任务状态
  • 日志、评测与运营监控
→

MES 数据服务层

  • 指标语义与数据契约
  • 用户数据范围过滤
  • 时序与历史分析服务
  • 计划模拟与预测服务

平台内部需要稳定的接口

  • Agent Definition：Agent 配置、版本和发布状态
  • Tool Contract：工具参数、返回结构、错误码和权限标签
  • Identity Context：用户、组织、角色和数据范围
  • Trace Event：问题、调用链、耗时、成本和结果状态

MES 侧需要沉淀的公共能力

  • 统一设备、人员、工单、班次和产线主数据
  • 产能、达成率、稼动率、节拍等指标口径
  • 面向 Agent 的聚合 API，避免直接生成任意 SQL
  • 数据新鲜度、缺失率和异常值的质量标记

权限模型建议

有效权限由三层取交集

用户权限控制谁能看什么；Agent 权限控制这个 AI 员工允许做什么；场景策略控制本次任务在什么条件下可以执行。

查询类操作

沿用 MES 组织与数据范围，结果按工厂、车间、产线、设备、人员和敏感字段过滤。报告缓存也必须带权限标签。

动作类操作

创建计划、修改参数、发送通知等动作默认要求人工确认。高风险动作进入审批，禁止模型直接提交生产控制指令。

AI 员工身份

每个 Agent 使用独立服务身份、最小权限和独立密钥，禁止多个 Agent 共享高权限账号，禁止把密钥写入提示词或连接器配置明文。

审计与追责

审计至少包含发起用户、Agent 版本、模型、数据范围、工具参数、结果、确认人、异常和成本。日志保留周期写入合同。

平台与替代基座的决策比较

决策维度公司 Agent 平台OpenClaw / Hermes 类基座建议
现有资产复用可复用模型、连接器、运营和团队经验需要重新适配 MES 与内部规范平台优先
业务交付一致性便于形成统一产品和售后体系灵活，但容易形成第二套技术栈平台优先
个人 AI 员工能力取决于现有记忆、长任务和渠道能力通常更强调个人自治、工具与消息渠道按差距验证
企业权限与审计可按公司标准统一建设需要专项加固和集成验证平台优先
可控性与责任版本、SLA、故障和路线由公司负责受社区迭代和开源依赖影响平台优先
适用位置主生产交付架构隔离试验、专项能力或备用方案主次分明
