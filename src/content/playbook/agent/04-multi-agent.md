多 Agent 不是把同一个问题同时问很多遍。它的价值来自明确分工、独立上下文和可合并的产物。

## 什么时候应该拆分

适合拆分的任务通常具有独立边界，例如不同模块实现、并行研究或相互独立的质量检查。

强依赖的连续步骤不适合并行。协调成本可能高于执行收益。

## 共享什么，不共享什么

多个 Agent 应共享目标、接口契约和验收标准，但保留各自的工作上下文。全量同步会迅速放大噪声。

## 合并与责任

系统需要一个明确的汇总责任方，检查冲突、验证组合结果，并决定是否完成任务。

## 本章检查

- 拆分后的任务是否可以独立推进。
- Agent 之间是否共享了必要契约。
- 最终结果是否有明确的合并与验收责任。
