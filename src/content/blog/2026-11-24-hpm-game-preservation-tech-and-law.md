这两天，我和 Codex 做了一个叫 [HPM](https://hpm.pub/) 的项目，中文名是“霍格沃茨纪念册”。起初的想法很简单：把《哈利波特：魔法觉醒》里熟悉的角色、衣服、魔杖和表情留下来，做成一个随时能打开的网页。

这个念头来自游戏的停运安排。官方在 11 月 16 日宣布，计划于 2027 年 3 月 3 日停止运营。写这篇文章时，游戏还没有停服。[官方停运说明](https://sina.cn/news/detail/5365894483280623.html)

回看 11 月 23 日到 24 日的 Codex 对话，需求扩展得很快。找到人物素材以后，我想要换装；找到寝室以后，我想切换四个学院；领舞、跟随和音乐都在，又想试试双人舞会。后来连决斗训练场也做出了本地首版。

直到准备继续公开这些功能时，我们才集中检查授权问题，并收缩了发布范围。这篇文章记录这段过程，也把技术上已经做到的部分、仍然缺失的部分，以及我现在对发布边界的判断写下来。

## 从素材目录做到能打开的纪念册

最初交给 Codex 的材料，是本机安装的游戏客户端。很快就发现，安装目录里的内容并不完整。部分衣服、宠物和外观需要在游戏里继续下载，资源才会落到本地。

这直接影响“完整归档”的含义。资源清单里有一个名字，只能说明客户端知道它；磁盘上有没有对应内容，还要另查。我们保留了基础包和后续下载的记录，也保留无法匹配的条目，没有把一次扫描当成全部素材已经收齐。

项目逐渐形成了三层：

| 层次 | HPM 中做的事情 | 留下的结果 |
| --- | --- | --- |
| 本地归档 | 读取资源包、配置和路径清单，记录文件来源 | 原始文件、索引、校验记录、失败清单 |
| 离线转换 | 解析贴图、模型、骨骼、动画与音频关系 | GLB、图片、动画数据和浏览器可播放的音频 |
| 网页运行 | 用 HTML、CSS、JavaScript 和 Three.js 组织交互 | 卡册、换装、寝室、舞会与决斗训练场 |

Python 主要留在前两层。网页读取转换好的数据，展示和角色渲染不需要 Python 服务。后来首页加入了烟花共享计数，才额外用了 Cloudflare Pages Function 和 D1；人物装扮、寝室选择等状态仍保存在浏览器。

最初的对话提到了 Craft Anything，但当前 HPM 实现没有集成它。实际工作由 Codex 配合本地解析与转换脚本、Three.js 和测试完成。项目里的 NeoX 解析代码，也只是读取相关资源格式的工具，不能等同于拿到了原游戏引擎。

归档做得有用，还需要补回素材之间的关系。一个魔杖名字，要关联中文配置、物品编号、模型、贴图、挂点和动作；一张卡牌，要把卡面、故事插画、GIF 和演示视频放在一起。少了这些关系，留下的只会是一批很难查找的文件。

## 模型能打开以后，问题开始变具体

我在对话里反馈最多的，是一些很直观的问题：脸怎么白了，眉毛怎么没了，魔杖角度为什么不对，换上礼服以后脖子怎么断开了。

这些问题很难靠“再优化一下画面”解决。每次都要回到原始资源，确认哪一层关系没有还原。

### 换装需要一整套装配关系

角色外观包含身体、头部、独立眼球、眉毛、头发、衣服和配饰。它们各自有模型、材质、骨骼或变形数据。把一个衣服模型换上去，只完成了其中一步。

露领礼服出现身体断层，需要检查衣服对应的身体部件；魔杖握持角度异常，要检查手部挂点、绑定姿态和动画；三种服装配色看起来一样，则要继续找材质变体和原始染色贴图。

瞳色和眉色还有一个细节：有些 RGBA 贴图的通道承担的是染色遮罩。把它当作普通透明图片处理，可能丢掉后续着色要用的数据。网页能加载图片，并不能证明这些通道被正确保留。

HPM 已经修复了一批此类问题，但布料摆动、折射、噪声和部分专用妆造仍与原 App 有差异。文章里可以说复用了原始模型和动作，不能据此宣称画面已经一比一还原。

### 舞会要先把时间对齐

本地舞会版本接上了两个场景和 39 支已匹配的双人舞曲。领舞与跟随要保留共同的舞池原点和移动轨迹，音乐、双方动作、镜头与音符则要使用同一条时间轴。

当前实现以音频播放时间加配置偏移驱动动作。这样音乐暂停或缓冲时，人物不会继续跳；拖动进度时，两个人也能一起切到对应姿态。分别启动几个计时器，很容易在播放一段时间后出现错位。

节奏试玩先接入《华尔兹：飞翔天际》一星谱面的 61 个点击点。当前全 Perfect 得分是 20,300，与原配置的单人满分一致。不过，浏览器判定窗仍是试玩参数，混合判定的最终分数也没有逐项对齐原 App。一个满分样例通过，只能验证这一条路径。

### 决斗还需要重新实现运行规则

决斗场第一版的视角不对，我要求回头查原场景。后来从场景文件里找到了左右对战的镜头方向和 5° 透视视野角，再结合网页尺寸调整距离与构图。模型导出中的坐标系转换，也必须和场景节点、镜头方向一致。

“石礅出动”的实现更能说明配置的价值。卡牌一路关联到技能、效果、召唤物、角色和属性表，才找到身体、武器、七段动作以及相关数值。网页再用固定 60 Hz 的模拟处理寻敌、移动、攻击、嘲讽和死亡。

但原配置里的 AI 标识和逻辑编号，背后还有引擎处理器。我们没有把这些处理器完整移植过来。当前训练场的状态调度、避让和部分特效采用网页实现，也没有完整联机、回响与卡组轮转系统。

因此，我把它叫作本地决斗训练场。它已经能演示几张卡牌的行为，距离完整游戏还有明确的缺口。

## 公开发布让我重新看了一遍授权

前面的迭代里，我们曾把素材预览、资源包和部分互动页面放到了网上。后来检查法律风险时，我确认没有取得覆盖游戏素材、相关 IP 和音乐使用的书面授权。

下面按中国大陆法律讨论这个项目遇到的问题，是开发复盘，不能代替律师结合具体素材、协议和传播范围作出的意见。

### 纪念用途不能代替素材授权

复制素材、转换格式、网页展示、提供下载，是需要分别审视的使用行为。模型转成 GLB、贴图转成 WebP，原素材的权利不会随格式变化而消失。《著作权法》第十条规定了复制权、信息网络传播权等权利；第二十四条的个人学习、研究或欣赏情形，有适用条件，不能直接推广到面向所有访客的完整素材库。[《著作权法》第十条、第二十四条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

对 HPM 来说，最容易误判的就是“只做展示”。浏览器要显示模型、播放音乐，仍然需要取得对应内容。去掉下载按钮，可以收缩产品功能，却不能据此断言公开传播已经停止。保留下来的图片和 GIF，也仍有授权问题。

“非商业”“版权归原作者”和权利人联系入口，都可以说明我们的态度，但不能替权利人作出许可。项目自己的 LICENSE 只能覆盖我们有权许可的原创部分。游戏停服也不会让仍在保护期内的作品自动进入公有领域。[《著作权法》第二十三条、第五十三条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

### 研究格式和分发素材要分别判断

《计算机软件保护条例》第六条区分了软件表达与思想、处理过程等内容，第十七条也为学习研究软件内含的设计思想和原理规定了相应空间。这些规定不能直接当作美术、音乐和模型的公开分发许可。[《计算机软件保护条例》](https://www.cac.gov.cn/2013-02/08/c_12648744.htm)

HPM 的本地提取脚本还包含资源解混淆处理。普通容器解析、解压缩，以及规避法律保护的技术措施，需要结合实际机制判断，不能只看文件后缀或算法是否简单。《著作权法》第四十九条、第五十条对技术措施及例外另有规定；即使符合反向工程研究例外，也不意味着可以向他人提供规避技术措施的技术、装置或部件，或侵犯其他权利。[《著作权法》第四十九条、第五十条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

所以，下面的实现方案只描述离线归档与转换流程。涉及保护措施的部分，需要先单独核实权限和法律依据，不能用“我已经安装了游戏”替代这一步。

### 字体、标识和第三方工具也在范围内

项目还用过游戏官网图标、分享图和游戏字体。这些内容需要独立核对使用许可。标识是否涉及商标侵权，要结合具体用途、注册范围和混淆可能判断；在文章里说明游戏名称，与把官方标识当成自己网站的识别标志，使用场景不同。[国家知识产权局公布的《商标法》文本](https://www.cnipa.gov.cn/art/2026/6/26/art_95_206942.html)

第三方工具也有自己的许可。HPM 本地保存的 NeoX 解析工具附带 AGPL-3.0 文本，其他运行库则可能采用不同条款。不能拿项目自写的“非商业许可”统一覆盖它们；分发哪些代码、是否修改、怎样提供服务，都应逐项核对。

首页烟花计数还带来了数据处理问题。当前业务接口使用学院、网络地区代码和事件编号，没有把原始 IP 写入这些业务表，但这不代表 CDN 日志和整个访问链路不涉及个人信息。后续仍需核实告知、处理依据和保存期限。[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

## 把本地实验和公开构建分开

检查之后，我们先撤下素材包和导出入口，又关闭了公开的寝室、舞会、决斗及影音播放。素材 Release 转为草稿，仓库改为私有，本地实验继续保留。

截至 11 月 24 日，项目记录中的发布范围是下面这样：

| 内容 | 本地完整版 | 公开精简版 |
| --- | --- | --- |
| 首页、卡册、图片和 GIF | 保留 | 保留，仍需核实素材授权 |
| 寝室、换装、舞会、决斗训练场 | 保留 | 不纳入构建 |
| 原始素材、可编辑模型、影音与处理工具 | 本机保存和使用 | 关闭相关分发与播放入口 |

这次调整落实到了构建代码。公开构建按明确的文件清单复制页面，只保留图片和 GIF 条目，并检查输出目录是否混入模型、压缩包、影音和字体等文件。构建缺少本地资源时会停止，不再自动从网络下载素材。

本地完整版使用独立入口，只监听 `127.0.0.1`。资源按需从本机读取，必要时校验本地资源包，再解压到缓存目录。公开构建和本地启动分别检查，避免一次试玩改动把实验模块重新带到线上。

撤下页面以后还要检查旧文件地址和缓存。开发记录里就遇到过页面已经关闭、域名缓存仍在提供旧模型的情况。把链接从导航里删除，不足以确认资源已经不可访问；已经被他人下载的副本，也无法靠修改仓库状态收回。

这些措施减少了继续公开传播的范围，没有替项目补上授权。保留的图片展示仍需审查，本地研究也仍需看资源来源、许可协议和提取方式。我不会把当前精简版称为已经完成法律合规。

## 一个够用的解包实现方案

如果把这次临时写出的处理脚本整理成一个更清楚的小工具，我会采用“扫描、提取、转换、预览”四个阶段。输入限定为来源合法、且对相应分析处理具有授权或明确法律依据的本地样本；先做最小样本验证，再扩大范围。

下面的格式细节来自 HPM 当前样本和脚本，不能当成适用于所有 NeoX 游戏、平台或版本的通用规格。

### 先建立索引，再写出文件

当前样本的资源包头标记为 `NXPK`。已有脚本会读取条目数量和索引位置，再从记录中取得文件签名、偏移、存储长度、原始长度与标志位。路径清单来自 `resdb`；路径规范化后，通过 MurmurHash3 与条目签名建立候选对应。

哈希匹配可能存在歧义。只在候选唯一时恢复路径，多候选和未匹配条目保留包名、签名、偏移及候选列表，放进单独的待确认区域。基础包和更新包也保留各自来源，明确覆盖顺序，避免同名文件被悄悄替换。

扫描阶段就应检查索引数量、偏移和长度是否落在包内。写文件前再限制输出路径，拒绝绝对路径和目录穿越；解压时设置单条目及总输出大小上限。校验失败应进入报告，不能只打印一行错误后丢掉记录。

### 按类型转换，保存原始输入

现有脚本已经包含原样读取、zlib 和 LZ4 分支。后续转换可以分开处理：

| 类型 | 处理方式 | 最先核对的内容 |
| --- | --- | --- |
| 纹理 | 识别容器和实际编码，解码 ASTC、ETC 等内容，生成预览 | 宽高、色彩、透明度与遮罩通道 |
| 配置 | 读取分片索引，解压对应片段，解析 MessagePack | 主键、引用、中文名称与资源路径 |
| 模型与动作 | 解析网格、骨骼、绑定姿态、权重与动画，转换为 GLB 或运行数据 | 坐标系、法线、骨骼索引和原始时长 |
| 音频 | 沿播放事件、音频 bank 与轨道关系定位内容，再按需转码 | 曲目对应、时长、起点和循环范围 |

转换结果放到独立目录，原始文件不覆盖。每个结果记录源包、条目、源内容摘要、转换参数和工具版本。这样遇到白脸、错色或动作错位时，可以回到具体输入重新处理。

整理后的主流程可以写成下面的伪代码。函数表示待实现的模块接口，省略具体保护措施处理，也没有联网获取或上传步骤。

```python
for package in local_packages:
    package_id = sha256_file(package)
    for entry in scan_index(package):
        try:
            check_bounds_and_size_limits(package, entry)
            candidates = resolve_manifest_paths(entry)

            if requires_protection_review(entry):
                record_pending(package_id, entry, candidates)
                continue

            raw = decode_plain_entry_with_limit(package, entry)
            check_original_size(raw, entry)
            source = save_local_original(raw, package_id, entry, candidates)
            preview = convert_supported_type(source)
            record_result(source, preview, sha256_bytes(raw))
        except DecodeError as error:
            record_failure(package_id, entry, str(error))
```

第一轮验收只需要选一张卡图、一件衣服、一支魔杖和一段动作，把来源记录与预览做通。图片核对透明度，模型核对朝向和挂点，动作核对时长；再加一个截断包、一个歧义路径和一个缺失依赖，确认它们能留在失败或待确认清单里。音乐和复杂场景可以随后接入。

HPM 目前留下了一套能本地打开的纪念册，也留下了不少还原过程中的记录。我接下来更愿意先补齐这些记录，把失败样本和近似实现标清楚。公开版本要继续扩展，就需要先明确素材授权，或者换成原创、明确许可的内容，再决定开放哪些功能。
