你说的：查一下上个月销量前十的商品，带分类和库存

AI 生成的 SQL：
SELECT p.name, p.category, SUM(oi.quantity) AS total_sold,
       p.stock_count
FROM order_items oi
JOIN products p ON oi.product_id = p.id
JOIN orders o ON oi.order_id = o.id
WHERE o.created_at >= DATE_SUB(CURDATE(), INTERVAL 1 MONTH)
GROUP BY p.id
ORDER BY total_sold DESC
LIMIT 10

日常 80% 的查询都能自动生成。复杂多表 JOIN 偶尔需要手动调一下，但起手速度比从零写快太多。AI 读表结构和字段注释理解业务语境，在数据集里配上术语之后准确度更高。

6 / 8 愿景

Chat2DB Agent：通用型 Agent 和数据库之间的桥梁

飞书做了 CLI 化让 Agent 可以操作企业协作工具，微信开放了 ClawBot 接口。Agent 生态正在成型。但通用型 Agent 想拿到企业数据，中间还缺一环。

为什么是 Chat2DB

  • 数据集、连接配置、权限都在 Chat2DB 里收口
  • 通用 Agent 不需要知道底层数据库类型和连接信息
  • Text2SQL + 数据集的业务术语，Agent 查数据比手写 SQL 更准
  • 数据安全在 Chat2DB 层统一管控，不暴露给上游 Agent

Agent2Agent 协作场景

  • 日程 Agent 查飞书日历 → 调 Chat2DB Agent 拉相关数据 → 自动出会前报告
  • 业务 Agent 接到数据需求 → 调 Chat2DB Agent 执行查询 → 结果回传 Dashboard
  • 运维 Agent 监控异常 → 调 Chat2DB Agent 查日志表 → 自动分析根因

通用型 Agent 擅长编排工作流，但不擅长直连数据库。Chat2DB Agent 把连接管理、数据集定义、安全管控全部收口，让通用 Agent 用自然语言就能拿到数据。Agent 生态里天然的"数据层 Agent"。
