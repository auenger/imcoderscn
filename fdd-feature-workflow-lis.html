01关键转变

从水平切片到垂直切片

交付方式决定团队组织方式

VS对比

水平切片（传统）

  • 数据库层 → 业务逻辑层 → API 接口层 → UI 展示层
  • 按技术层分工，完成后才看到完整功能
  • 前端组 / 后端组 / DBA 组

垂直切片（FDD）

  • 特性 A：用户登录（DB→逻辑→API→UI）
  • 特性 B：订单查询（DB→逻辑→API→UI）
  • 特性 C：支付流程（DB→逻辑→API→UI）
  • 每个特性横跨所有层，独立可交付

FDD 的"特性"天然就是垂直切片 — 一个对用户有价值的小功能，必须横跨所有技术层。

A2附录

FDD vs Scrum

FDD（特性驱动）

  • 关注点：工程实践、架构和代码质量
  • 迭代单位：特性（Features）
  • 代码归属：明确的类负责人制
  • 适用场景：中大型项目，对架构要求较高
  • 设计方式：先建模再按特性切分
  • 进度可视：特性完成进度（看板）

Scrum（迭代驱动）

  • 关注点：过程管理、团队协作和交付节奏
  • 迭代单位：冲刺（Sprints）
  • 代码归属：团队共同拥有代码
  • 适用场景：各种规模，强调快速反馈
  • 设计方式：按冲刺批量处理
  • 进度可视：Burndown 图

FDD 关注怎么写好代码，Scrum 关注怎么管理过程。两者可以互补 — 用 Scrum 管节奏，用 FDD 管工程质量。
