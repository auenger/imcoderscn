模式 1

四层分离架构

把 skill 知识按加载时机分四层，每层职责清晰。

Layer 0: Frontmatter~200 tokens · 触发判断
Layer 1: 决策框架~500 tokens · 流程骨架
Layer 2: 关键约束~1K tokens · 不可违反
Layer 3: 数据层CSV/JSON · 按需检索

核心思想

SKILL.md 只放「路由和红线」，详细知识外置到数据层。触发时加载轻量框架，按需检索细节。

收益

  • 上下文从 44KB 降到 5-8KB
  • 数据层可独立更新
  • 不同场景只加载需要的知识

模式 3

领域驱动的数据索引

11 个搜索域

style / color / typography / chart / ux / product / landing 等

独立配置

每个 domain 有自己的 CSV、search_cols、output_cols

自动检测

"glassmorphism dark" → style 域。"saas dashboard" → product 域

可扩展

新增领域只需：加 CSV + 加配置 + 加关键词映射

领域划分让 skill 从「一个大搜索框」变成「结构化的知识路由」。AI 不需要读完全部数据，直接命中目标域。

模式 4

合成推理器：不止搜索

`--design-system` 聚合多域 + reasoning 规则，输出结构化推荐。

用户输入 "SaaS 定价页"
→
并行搜索 5 域
→
Reasoning 推理
→
合成设计系统

五域并行

  • product → 产品类型
  • style → UI 风格
  • color → 色彩方案
  • landing → 页面结构
  • typography → 字体

Reasoning 层

  • ui-reasoning.csv 决策规则
  • 产品类型 → 推理链匹配
  • 输出 style_priority
  • 结果比单域更结构化

模式 5

优先级分层：让 AI 知道轻重

CRITICAL
无障碍 · 触摸交互 — 违反即事故
HIGH
性能 · 布局 · 导航 · 风格 — 影响体验
MEDIUM
排版 · 动画 · 表单 — 锦上添花
LOW
图表 · 数据可视化 — 特定场景

借鉴价值：给 AI 一套「什么能违反什么不能」的决策框架。没有优先级的规则列表，AI 会同等对待所有条目。

模式 6

Master + Overrides 有状态持久化

design-system/
├── MASTER.md          ← 全局 Source of Truth
└── pages/
    ├── dashboard.md   ← 页面级 override
    └── checkout.md    ← 页面级 override

层级检索逻辑

  • 构建 dashboard → 先查 pages/dashboard.md
  • 存在则 override 优先
  • 不存在直接用 MASTER
  • 一次生成，多次复用

适用场景

  • 跨 session 保持一致性
  • 多页面统一设计语言
  • 设计决策可追溯
  • 新成员 onboarding 参考

模式 7

渐进式加载：按需逐步展开

Step 1 SKILL.md ~5KB
→
Step 2 --design-system
→
Step 3 --domain ux
→
Step 4 --persist
每一步只加载当前需要的知识。Token 消耗与场景复杂度成正比，而非全量灌入。

设计原则

SKILL.md 是索引器和决策路由，不是百科全书。告诉 AI「去哪里找答案」。

Token 效率

简单任务 ~2KB，复杂项目渐进到 ~10KB。而非每次固定 ~44KB。

核心理念

好的 Skill 是高效的索引器和决策路由，不是百科全书。

把知识外置到数据层，把路由和红线留在 SKILL.md。按需检索替代全量加载，合成推理替代简单搜索，有状态持久化替代无状态重复。
